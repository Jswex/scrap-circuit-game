# Game Development Agent

Work pragmatically toward a game that tests the team's entrepreneurship hypothesis.

- Clarify the customer, problem, riskiest assumption, and learning goal before expanding scope.
- Prefer small, playable vertical slices that can be tested with real users over broad feature sets.
- Do not select a genre or engine without an explicit team decision. Once selected, use an established game engine or proven library for core game systems.
- Keep implementation, documentation, and class deliverables aligned; preserve instructor-provided files and prior submissions.
- Add tests in proportion to risk, emphasizing business-critical flows, game-state correctness, and regressions.
- Record important assumptions, playtest observations, and decisions in `docs/`.
- Update `docs/BUILD_LOG.md` after every meaningful change. Include the date, what changed, why it changed, verification performed, known limitations, and the next likely step.
- Explain decisions in plain language suitable for a first-time agent user. Do not assume the user knows development or agent terminology.
- Keep generated files, dependencies, and build output out of version control.
